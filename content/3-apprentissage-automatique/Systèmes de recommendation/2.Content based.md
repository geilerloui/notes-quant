\section{Content-Based Recommender System}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{Introduction}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\textbf{Definition (Content-Based RS).} The main idea is to recommend items to customer $\mathbf{x}$ which are similar to the previous items rated highly by $\mathbf{x}$.\\

We start with an user and we find out a set of items a user like using both explicit and implicit data. For example, we can look at the items the user has rated highly and what he has purchased. For all those items we will build an item profile. An item profile is a description of the item, for example, the user like red circle and red triangle, the item might say the user like the red color and circle. Next, from the item profile we infer a user profile, here because the user like red circle and triangle we infer he likes red, circles and triangles. Once we have a profile we can match it to the catalog, some of the items are red so we can recommend it to the user.



![[images/3-Apprentissage automatique/10_Recommender system/2.Content based/intro-1.png|280]]
caption{The Content-based workflow}


\textbf{Examples.} (i) Movies - we might recommend movies with the same gender, actor. (ii) Websites, blogs, news - we might recommend articles with similar content/topic (iii) People - We might recommend people with many common friends between each other.\\



\textbf{Pros.}
\begin{itemize}
    \item (i) We do not need data on other users 
    \item (ii) We are able to recommend to users with unique tastes, with CF we need to find other similar user, the problem is that if we have a very unique user it might not fall into any group
    \item  (iii) We are able to recommend new and unpopular items. When a new item comes in we do not need any rating it only relies on the features of the items, we do not have the "first-rater problem".
    \item (iv) We have explanations for recommended items - in particular you can just list the content features, if you recommend a news article you might say that in the past the user read a lot of article on Syria.
\end{itemize}



\textbf{Cons.} 

\begin{itemize}
    \item (i) Finding the appropriate features is hard. For example how to find features for images, movies (we have proposed a set of features, but actors, directors are not the best), music 
    \item (ii) Overspecialization - the user profile is built using the item profile from what the user previously purchased/rating, if a user never rated a specific gender he will never be recommended a movie or piece of music outside of his references. Also it is unable to exploit the quality judgments of other users, for example there might a certain video or movie that is widely popular, however the current user never express any interest for that kind of movie so the Content-based RS will not recommend it
    \item  (iii) The cold-start problem for new users. In most practical situation new user have an average profile and over time the user profile evolve it becomes more individualize.
\end{itemize}

\subsection{User and Item profiles}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%


\textbf{Definition (Item Profiles).} For each item, we create an item profile. A profile is defined as a set of features. Mathematically the item profile is summarized in a single vector..\\

For example: (i) Movies - it might include, author, title, actor ... (ii) Images, videos - we can extract metadata and tags (iii) People - It can be a set of friends.\\

Special case - The Doc profile - we might include the set of words with the highest tf-idf scores.\\



\textbf{Definition (User Profiles).} Let's say we have a user who rated items with profiles $i_1, ..., i_n$ (where each $i_j$ is a vector). The simplest way to define a user profile is just a weighted average to take into account that user might like some items more
$$
\frac{1}{N} \sum_{j=1}^{N} \omega_j \cdot i_j
$$
A variant of that is to normalize weights using average rating of user. More sophisticated aggregations are possible.\\

\textbf{Definition (Making predictions).} Let $x$ be the user profile and let $i$ be item profile. We estimate by
$$
u(x,i) = cos(\theta) = \frac{(x \cdot i )}{||x|| \cdot ||i||}
$$


\textbf{Example 1 (Boolean utility matrix).} An example is whether a customer has bought an item or not. Or in the movie industry we define a feature of "Actor" - the item profile is a vector of 0 or 1 for each Actor if he appeared in the movie or not.\\

Suppose the user $x$ has watched five movies - 2 movies featuring actor $A$. Three movies featuring actor $B$. We define the user profile as the mean of item profile. Thus, Feature $\mathrm{A}^{\prime}$ s weight $=2 / 5=0.4$ and Feature $\mathrm{B}^{\prime}$ s weight $=3 / 5=0.6$\\

\textbf{Example 2 (Star Ratings).} Suppose we have 1-5 star ratings. The users rated the movies 3 and 5 where actors A played. And he rated the movies 1,2 and 4 where actor B played.\\

A useful step is to normalize ratings by subtracting user's mean rating. Actor $\mathrm{A}^{\prime}$ s normalized ratings $=0,+2$. Profile weight $=(0+2) / 2=1$. Actor B's normalized ratings $=-2,-1,+1$, Profile weight $=-2 / 3$
