# Content-Based Recommender System

## Introduction

**Definition (Content-Based RS).** The main idea is to recommend items to customer $\mathbf{x}$ which are similar to the previous items rated highly by $\mathbf{x}$.

We start with a user and we find out a set of items a user likes using both explicit and implicit data. For example, we can look at the items the user has rated highly and what he has purchased. For all those items we will build an item profile. An item profile is a description of the item — for example, if the user likes a red circle and a red triangle, the item profile might say the user likes the red color and circles. Next, from the item profile we infer a user profile: here, because the user likes red circles and triangles, we infer he likes red, circles, and triangles. Once we have a profile we can match it to the catalog — some of the items are red, so we can recommend them to the user.

*The Content-based workflow*

**Examples.**
- **Movies** — we might recommend movies with the same genre, actor.
- **Websites, blogs, news** — we might recommend articles with similar content/topic.
- **People** — we might recommend people with many common friends between each other.

**Pros.**
- We do not need data on other users.
- We are able to recommend to users with unique tastes. With CF we need to find other similar users — the problem is that if we have a very unique user, they might not fall into any group.
- We are able to recommend new and unpopular items. When a new item comes in we do not need any rating, it only relies on the features of the item — we do not have the "first-rater problem".
- We have explanations for recommended items — in particular you can just list the content features; if you recommend a news article you might say that in the past the user read a lot of articles on Syria.

**Cons.**
- Finding the appropriate features is hard. For example, how to find features for images, movies (we have proposed a set of features, but actors, directors are not the best), music.
- **Overspecialization** — the user profile is built using the item profile from what the user previously purchased/rated; if a user never rated a specific genre he will never be recommended a movie or piece of music outside of his references. Also it is unable to exploit the quality judgments of other users — for example there might be a certain video or movie that is widely popular, however the current user never expressed any interest in that kind of movie, so the Content-based RS will not recommend it.
- The cold-start problem for new users. In most practical situations new users have an average profile, and over time the user profile evolves — it becomes more individualized.

## User and Item Profiles

**Definition (Item Profiles).** For each item, we create an item profile. A profile is defined as a set of features. Mathematically the item profile is summarized in a single vector.

For example: (i) Movies — it might include author, title, actor... (ii) Images, videos — we can extract metadata and tags. (iii) People — it can be a set of friends.

Special case — the Doc profile: we might include the set of words with the highest tf-idf scores.

**Definition (User Profiles).** Let's say we have a user who rated items with profiles $i_1, \ldots, i_n$ (where each $i_j$ is a vector). The simplest way to define a user profile is just a weighted average, to take into account that the user might like some items more:

$$\frac{1}{N} \sum_{j=1}^{N} \omega_j \cdot i_j$$

A variant of that is to normalize weights using the average rating of the user. More sophisticated aggregations are possible.

**Definition (Making predictions).** Let $x$ be the user profile and let $i$ be the item profile. We estimate by:

$$u(x,i) = \cos(\theta) = \frac{x \cdot i}{\|x\| \cdot \|i\|}$$

**Example 1 (Boolean utility matrix).** An example is whether a customer has bought an item or not. Or in the movie industry, we define a feature "Actor" — the item profile is a vector of 0 or 1 for each actor, depending on whether he appeared in the movie or not.

Suppose user $x$ has watched five movies — 2 movies featuring actor $A$, 3 movies featuring actor $B$. We define the user profile as the mean of item profiles. Thus, feature $A$'s weight $= 2/5 = 0.4$ and feature $B$'s weight $= 3/5 = 0.6$.

**Example 2 (Star Ratings).** Suppose we have 1-5 star ratings. The user rated the movies 3 and 5 where actor $A$ played, and rated the movies 1, 2 and 4 where actor $B$ played.

A useful step is to normalize ratings by subtracting the user's mean rating. Actor $A$'s normalized ratings $= 0, +2$. Profile weight $= (0+2)/2 = 1$. Actor $B$'s normalized ratings $= -2, -1, +1$, profile weight $= -2/3$.
