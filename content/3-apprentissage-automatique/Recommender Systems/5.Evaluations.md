# Evaluation for Recommender Systems

## Data Splitting

Given a matrix with features: $\{uid, iid, rating, timestamp\}$.

**Random.** We can split the data randomly for each user $uid$.

**Sequence aware.** Otherwise we leverage the timestamp to split the data. For example we can hold out the last three purchases of a user, and next we have to predict them.

## Scores

### Root Mean Square Error (RMSE)

The common methodology is to take a piece of the matrix and use it as the test dataset. We actually know some of those ratings, so we can use them and compute a score.

![[images/3-Apprentissage automatique/10_Recommender system/5.Evaluation/eval-1.png]]

**Definition (RMSE).**

$$\boxed{RMSE = \sqrt{\frac{\sum_{(x,i) \in T} \left(r_{xi} - r_{xi}^\star\right)^2}{N}}}$$

where $N = |T|$, $r_{xi}$ is the predicted rating and $r_{xi}^\star$ is the actual rating.

**Problems with RMSE.** RMSE misses the point of why we implement RS in the first place. Remember: the goal of RS is not to predict the rating of a user but to recommend items to the user that he might buy or listen to. So if you optimize purely for the highest score you might end up with problems:
- **Prediction Diversity.** Predictions are too similar to each other. For example the user liked the first Harry Potter — the set of most similar items might be the other Harry Potter movies, which is not a very diverse set of movies.
- **Prediction context.** The same user might be operating in different contexts. For example, if the user is traveling in Patagonia he looks for a lot of books on Patagonia; once he gets back home he is no longer interested in this topic.
- **Order of predictions.** For CDs, books, or movies, you want to recommend items that are earlier in the sequence rather than the last one. For example, after the user has watched the first HP movie, he might want to see the second one and not the third.

### Precision and Recall at top $k$

**Motivation.** We have a website where people post pictures. They can rate pictures on a range of 1 to 5 points, where 1 stands for the user disliking it and 5 for totally liking it. First let's write down the true values:

![[images/3-Apprentissage automatique/10_Recommender system/5.Evaluation/im1-1.png]]

Then our model predicts the following data:

![[images/3-Apprentissage automatique/10_Recommender system/5.Evaluation/im1-2.png]]

Similar to what we have encountered in ML, we can compute the recall, accuracy and precision, first noting that $TP=2$, $TN=2$, $FP=2$, $FN=0$. This lets us calculate:

- $Accuracy = \dfrac{2+2}{6} = 0.67 \Rightarrow 67\%$ accuracy
- $Precision = \dfrac{2}{2+2} = 0.5 \Rightarrow 50\%$ precision
- $Recall = \dfrac{2}{2+0} = 1 \Rightarrow 100\%$ recall

![[images/3-Apprentissage automatique/10_Recommender system/5.Evaluation/im1-5.png]]

The problem with this approach is that typically the user did not have any experience with a picture of a "cat". As such, should it count as a false positive or a true positive? We must resort to a different solution.

**Definition (Relevant).** The pictures that the user already liked.

**Definition (Recommended).** The pictures that are in the predicted list.

**Definition (Precision and Recall @ $k$).** First we sort the predictions by rank. Formally define $\omega(r)$ as the item at rank $r$, $\mathbb{I}[\cdot]$ the indicator function, and $I_u$ the set of held-out items that user $u$ clicked on.

$$\begin{aligned}
Precision &= \frac{|\text{recommended} \cap \text{relevant}|}{|\text{recommended}|} \\[4pt]
Recall &= \frac{|\text{recommended} \cap \text{relevant}|}{|\text{relevant}|} \\[4pt]
\text{Recall@}R(u,\omega) &= \frac{\sum_{r=1}^R \mathbb{I}[\omega(r) \in I_u]}{\min(M, |I_u|)}
\end{aligned}$$

**Example (Continued).** We take $k=3$ in our example (already sorted). We have two "Relevant" items: "Car" and "Girl". All three items have been predicted (recommended).

$$Precision = \frac{2}{3} = 0.67 \qquad Recall = \frac{2}{2} = 1$$

![[images/3-Apprentissage automatique/10_Recommender system/5.Evaluation/im1-3.png]]

**Example (Continued 2).** We have two relevant items (the pictures the user likes in the initial data), "Car" and "Girl", along with two recommended items, "Car" and "Girl".

$$Precision = \frac{2}{2} = 1 \qquad Recall = \frac{2}{2} = 1$$

![[images/3-Apprentissage automatique/10_Recommender system/5.Evaluation/im1-4.png]]

**Definition (Truncated Discounted Cumulative Gain, DCG).**
- *Motivation.* With Recall or Precision @ $k$, we consider all items ranked within the first $R$ to be equally important.
- *Formula.*

$$DCG@R(u,w) = \sum_{r=1}^R \frac{2^{\mathbb{1}_{w(r) \in I_u}} - 1}{\log(r+1)}$$

**Definition (Normalized Discounted Cumulative Gain, NDCG@r).** NDCG@r is DCG@r linearly normalized to $[0,1]$, dividing by the best possible DCG@r (where all held-out items are ranked at the top).

**Definition (Mean Average Precision, MAP).**

$$MAP = \frac{\sum \text{ratings of recommended items}}{\text{N recommended items}}$$

**Example.** With this metric we don't care about negative results — as we move from left to right, we count the positive results in the denominator.

$$MAP = \frac{1 + 0.67 + 0.75 + 0.67}{4} = 0.77 \Rightarrow 77\%$$
